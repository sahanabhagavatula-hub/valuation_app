Color audit

Untokenized accent

src/tokens.css declares one accent (--accent: #3FBF6F, green) plus a gold and a danger red. But a second accent — teal #4FC3C7 — is used 167 times across theme.css (almost as often as the official green, at 169) for every lesson page's tabs, active states, star points and badges, and it has no token entry at all. Two competing "primary" accents, one of them invisible to anyone reading tokens.css.

Tabs / toggle buttons

2 color outliers

Three-Statement Model uses off-white and LBO Modeling uses taupe instead of #4FC3C7. Looks like an accidental copy-paste drift rather than an intentional choice.

Takeaway / callout boxes

5 intentional variants

Every lesson topic rotates through the same five callout treatments (clay, dashed, quote, rule, and a one-off "star" variant for interactive-diagram lessons) — that variety looks deliberate, so it's not a bug. The bug is that all five are copy-pasted per page prefix instead of defined once and shared — see CSS duplication below.

CSS duplication

~3,000 lines, mostly copies

theme.css is 3,191 lines. Each lesson topic gets its own class prefix (bhv, lbo, pta, ccm, ...) and most of those prefixes redeclare the identical tab / panel / takeaway / quiz-choice rule sets verbatim. The count below is unique classnames per prefix — high counts are mostly duplicate boilerplate, not unique design.

Consolidating the shared 20–30 classes per prefix into one .valufin-lesson-* set (parameterized by a data attribute or CSS variable for the rare per-lesson color swap) would cut theme.css by roughly half.
